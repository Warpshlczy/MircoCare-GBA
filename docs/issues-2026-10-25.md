## Issue 1（A ↔ C）

**标题**：A ↔ C：Agent 新增 `log_medication` / `compose_card` 工具与 `record` 卡片契约（A 端已落地，待 C 对齐）

**正文**：

### 背景

按产品最新六项需求，A 端已落地「吃药语音记录 + 本机持久化 + Agent 自写卡片脚本 + 取消 NFC」。以下是与 C 侧 `/agent/turn` 的契约差异，请确认后对齐。

### 1. 工具表由 12 → 14

新增两个 `risk: "safe"` 工具（`web/src/lib/tools.ts`）：

| 工具 | 入参 | 说明 |
|---|---|---|
| `log_medication` | `{name?: string, note?: string}` | 老人报告「我食咗藥」时记录一次剂量。**问句/否定句不得调用**（`食咗藥未呀`、`我未食藥`）。副作用仅在端内：写 `records`、勾掉对应药类任务、清当日提醒 |
| `compose_card` | `{script: string, kind?: "measure"｜"med"｜"alarm"｜"card"}` | Agent 自建卡片。`script` 是纯文本 DSL，一行一条指令：`title:` / `icon:` / `headline:` / `row: 标签 = 值` / `check: [x] 文本`。**禁止 HTML/JS/URL** |

请 C 端：

1. 在 system prompt 里说明这两条工具的存在与边界（尤其「报告已吃」vs「提醒我吃」）；
2. `/agent/turn` 返回的 `calls` 允许出现这两个名字（A 端会按 schema 校验，未注册工具一律丢弃）；
3. 模型返回 `compose_card` 时，把 `script` 作为纯文本透传，不要做 HTML 包装。

### 2. 卡片 kind 增加 `record`

`CardKind` 现有 8 种，新增 `"record"`（今日记录卡）。返回结构仍是 `data`（前端结构化渲染）或 `html`（沙箱 iframe）。**记录卡必须走 `data`**，不要下发 html——端内不会执行脚本。

### 3. 记录同步（待讨论，不阻塞）

A 端目前把吃药/闹钟/测量记录**只存本机 IndexedDB**（`records` store，DB v6），不上传。若家属端需要「今日是否已服药」，请提一个最小接口（建议 `POST /records/summary`，只传 `{day, kind, count, lastAt}` 这类粗粒度聚合，不传药名原文），A 端再接。是否要做，请 C 决策并回复本 issue。

### 4. 已删除的字段

`MedItem.nfcTag` 已删除（NFC 方案取消）。若 C 端 mock 或契约里有该字段，请同步移除。

### A 端现状

- `npm run selfcheck` / `npm run typecheck` / `npm run build` 全绿
- 自检覆盖：重复上报不写第二条、恶意 `<script>` 被剥离、空脚本返回可播报的失败文案
- 详细改动见 `docs/dev.md` §2.4 A7 与 §3.5

## Issue 2（A ↔ B）

**标题**：A ↔ B：记录卡上桌面小组件、原生闹钟与新增/删除字段对齐，后台跌倒采样需同阈值

**正文**：

### 背景

A 端本轮把吃药改为「语音记录 + 本机持久化 + 卡片可勾」，并收紧了跌倒阈值。以下三处需要 B 端的原生侧对齐。

### 1. 桌面小组件要能显示记录卡

- 新增 store：`records`（`DB_VERSION` 5 → 6，`web/src/lib/db.ts`），字段 `{id, kind: "med"｜"alarm"｜"measure"｜"card", title, detail?, at, day, source}`。
- 新增卡片 kind：`"record"`，`data.checklist` 里每条 `done: true`（记录不是待办）。
- `homeWidgetPayload()` 目前只吃 `cards[]` 与 `reminders[]`。请确认原生 `HomeWidgetProvider` 是否需要：
  1. 在 2×2 小组件顶部加一行「今日記錄」（例如 `💊 08:12 食藥`）；
  2. 点击该行时通过 deep link 回到 App 的「今日記錄」卡片。

### 2. 原生闹钟要持久化并对齐

- 现在 `set_alarm` 成功后会写一条 `records` 记录（`kind: "alarm"`，`detail` 是「今日8點」这类人话）。
- Web 侧 App 关闭时不会到点弹窗（README 已声明天花板）。请 B 端确认：
  1. 原生 `AlarmManager` 的已排闹钟是否也需要持久化（重启后重排）；
  2. App 被系统杀掉再打开时，能否用 `records` 里的 alarm 记录做一次校准（避免重复排或漏排）。

### 3. 跌倒阈值已收紧，原生后台采样必须一致

`web/src/lib/signal.ts` 默认值变更：

| 参数 | 旧 | 新 |
|---|---|---|
| `accThreshold` | 10 | **28** |
| `freeFallG` | 0.5 | **0.35** |
| `restBandG` | 2.5 | **1.5** |
| `stillnessMs` | 300 | **1500** |

并且：无自由落体阶段时，必须 `jump > 56 m/s²` 且 `gyro > 12` 才算撞击（防止桌面撞击/掉手机误报）。

请 B 端：

1. 若 `WakeListenService` / 原生前台服务里也有一份跌倒判定，改成同一组阈值；
2. 后台采样频率若低于 20 Hz，1.5s 静止窗口仍可判定，但需要保证窗口内至少 10 个样本；
3. 确认 `GaitWindow.fall` / `fallReason` 字段不需要改（A 端未改契约）。

### 4. 已删除

- `web/src/lib/nfc.ts` 整个文件删除；`MedItem.nfcTag` 删除。原生侧若有 NFC 相关 intent-filter / 权限申请，请一并移除。

### A 端现状

- 记录只在本机，不上传；埋点仍是粗粒度计数
- 自检新增：轻敲不触发、无失重的桌面撞击不触发、真实重摔仍触发一次
